# 后台架构与商业化方案

> 这份文档是工程与产品层面的建议,**不是法律或税务意见**。涉及合同、收款、备案、个人信息的部分,正式上线前请咨询专业人士。

## 0. 先说清楚「你能控制什么」

时序的客户端(网页、Windows 程序)是 AGPL 开源的,任何人都能拿到、修改、自己部署。**你无法控制别人手里的那份代码,你能控制的只有「你自己运营的服务器」。** 所以商业化的支点不是「锁住软件」,而是「你运营的、别人愿意付费的服务」。

## 1. 许可策略:AGPL + 双重授权

| 对象 | 怎么授权 |
|---|---|
| 个人、学校、自建部署 | AGPL-3.0,免费。修改后对外提供网络服务必须公开改动 |
| 想闭源集成、或不愿公开修改的公司 | 向你(版权持有人)购买**商业授权** |
| 外部贡献者 | 通过 `CLA.md` 授予你再许可的权利,否则你以后无法单独出商业版 |

要点:
- 双重授权的前提是**所有代码的版权都在你手里或已被 CLA 授权**。接受外部 PR 前,务必让对方同意 CLA(PR 模板里已有勾选项;可再接入 cla-assistant.io 自动检查)。
- 只有你有权出商业授权,别人 fork 后没有这个权利。
- 注册商标(名称、图标)是另一层保护:AGPL 不授予商标权,可防止别人用同名同图标卖「官方版」。

## 2. 收什么钱:收「服务」,不收「本地功能」

本地功能(排程、课表、长期事项、导出)应保持免费,这是开源项目的信誉,也是增长来源。适合收费的是你运营的东西:

| 收费点 | 为什么用户愿意付 | 备注 |
|---|---|---|
| 托管同步 | 不想自己搭服务器,多设备开箱即用 | 数据端到端加密,你读不到内容,成本也低 |
| 托管 AI 额度 | 不想自己申请 Key、不想处理跨域和国内访问 | 成本最高,必须按额度计量 |
| 优先支持、定制 | 团队/学校使用 | |
| 商业授权 | 公司要闭源集成 | 一次性或年费 |
| 团队版(后续) | 共享课表、共享日程 | 需要账号体系 |

## 3. 现在已经有的最小后台(本次交付)

位置:`cloud/`。技术栈:Cloudflare Pages Functions + KV,无需服务器,免费额度够起步。

| 能力 | 说明 |
|---|---|
| 管理页面 `/admin` | 概览、授权码管理、公告与开关。登录用管理员口令 |
| 授权码 | 批量生成、停用/恢复、延期、清设备、删除;每个码有设备数上限与到期时间 |
| 设备登记 | 客户端校验时登记设备编号,超过上限拒绝 |
| 公告 | 在客户端顶部显示,用户可关闭;内容改变才会再次弹出 |
| 最低版本 | 低于该版本的客户端提示刷新更新 |
| 维护模式 | 开启后同步与代理返回 503,客户端提示「本地使用不受影响」 |
| 要求授权码 | 开启后,你托管的同步与 AI 代理必须带有效授权码。**默认关闭**,所以开源自建者不受影响 |
| AI 代理开关 | 一键关闭托管的 `/proxy`,止损用 |

它看不到什么:概览只有数量。同步内容是端到端加密的,后台读不到任何用户的事项、设置、API Key。

### 部署步骤
1. 按 `部署到Cloudflare.md` 部署到 Pages 并绑定 KV(变量名 `CHRONO`)。
2. 设置管理员口令:Cloudflare 控制台 → Pages 项目 → Settings → Variables and Secrets → 添加 **Secret**,名称 `ADMIN_TOKEN`,值用**至少 24 位的随机字符串**(口令少于 16 位后台会拒绝登录)。保存后重新部署一次。
3. 打开 `https://你的域名/admin`,用该口令登录。
4. **强烈建议**再用 Cloudflare Access(Zero Trust)给 `/admin*` 加一层登录保护(邮箱一次性验证码即可,个人免费),这样即使口令泄露也进不去。
5. 想收费时:在「公告与开关」里打开「同步与 AI 代理要求授权码」;在「授权码」页生成码发给买家;买家在 设置 → 账号与授权 输入。

## 4. 分阶段路线

**阶段 0(现在)——手工发码**
你用后台生成授权码,通过微信/邮件/发卡平台发给买家。适合验证「有没有人愿意付费」。不需要写任何支付代码。

**阶段 1——自动发码**
接入收款平台,支付成功后自动调用「生成授权码」并发给买家。
- 国内个人主体:通常需要借助第三方的聚合/发卡/赞助平台,因为直接开通微信/支付宝商户需要主体资质。选哪家、费率与合规请自行核实。
- 海外:Stripe、Paddle、Lemon Squeezy 等,支持订阅与税务代缴(以各平台现行政策为准)。
- 实现方式:在 `cloud/functions/api/` 增加一个 webhook 函数,验证签名后调用与管理后台相同的生成逻辑。

**阶段 2——账号与用量**
- 引入账号(邮箱登录),授权从「授权码」升级为「账号订阅」。
- 托管 AI 代理按账号计量额度:在代理函数里记录用量、超额拒绝或提示购买。
- 从 KV 迁移到 D1(SQL),以便做统计、对账、审计日志。

**阶段 3——团队与学校**
共享课表、共享日程、管理员视图。需要完整的权限模型,工作量显著增加,建议有付费需求验证后再做。

## 5. 安全清单(上线前逐项确认)

- [ ] `ADMIN_TOKEN` 是随机的长字符串,只存在 Cloudflare Secret 里,不写进代码和 README。
- [ ] 已用 Cloudflare Access 保护 `/admin*`。
- [ ] 打开 Cloudflare 的速率限制规则(WAF → Rate limiting),至少限制 `/api/license/verify` 与 `/api/admin/*`,防暴力猜码和猜口令。
- [ ] 授权码长度 16 位字符(约 80 位熵),不可被枚举;管理页里不展示完整设备 ID。
- [ ] 定期导出备份(KV 数据可用 wrangler 导出)。
- [ ] 开启 AI 代理前先设上限:Anthropic/OpenAI 等控制台里给 Key 设置月度预算,避免被刷爆。
- [ ] 代理只允许白名单域名(已实现),新增服务商时改 `cloud/functions/proxy.js`。

## 6. 隐私与合规提醒

- 产品承诺的「数据在设备上加密、服务器只见密文」是你的核心卖点,**不要为了方便增加读取用户内容的统计**。要做数据分析,只收集匿名的功能使用计数,并在隐私政策中说明、提供关闭。
- 面向用户提供服务时,通常需要:隐私政策、用户协议、联系方式。涉及个人信息保护的具体要求请对照所在地法律并咨询专业人士。
- 如果服务器在中国大陆境内并绑定域名,通常需要 ICP 备案;提供生成式 AI 服务还可能有额外的备案与安全评估要求。**用 Cloudflare 的海外节点与「用户自带 Key」可以降低这方面的复杂度**,但是否适用于你的情况,请向主管部门或专业人士确认。
- 收款、开票、纳税:个人与公司主体差异很大,请咨询会计或税务专业人士。

## 7. 已知限制(诚实列出)

- **授权是「软控制」**:客户端开源,懂技术的人可以改掉校验。真正的控制点在服务端(同步、AI 代理),这也是为什么只对托管服务收费。
- KV 是最终一致的:授权码被停用后,全球各节点可能有最多约一分钟的延迟。
- 目前**没有账号体系、没有支付、没有速率限制、没有审计日志**,这些在路线图的后续阶段。
- 授权码列表在 KV 里全量读取,适合几千个以内;更大规模请迁移到 D1。
- 管理页面没有做多管理员与权限分级,只有一个管理员口令。
- 后台代码已有自动测试(`tests/cloud.test.js`,39 项),但**还没有在真实 Cloudflare 环境里部署验证过**,第一次部署请按清单逐项测试。
